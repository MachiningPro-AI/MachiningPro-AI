# Stock Removal Simulation

**Module:** MACHININGPRO_AI_REAL_CAM_TOOLPATH_STOCK_REMOVAL_SIMULATION_01
**Date:** 2026-11-25
**Status:** ACTIVE

---

## Overview

The workspace simulation system runs the Level-11 verification engine against
toolpath segments generated by the workspace CAM plan or any other toolpath
source. All simulation is performed offline — no CNC communication takes place.

> **Safety Statement:** A VERIFIED simulation result does **not** imply
> machining approval. Verification is an offline mathematical check;
> production release requires separate engineering sign-off.

---

## Simulation Pipeline

```
ToolpathLineGroups (frontend)
  → toolpathGroupsToSimSegments() [workspaceCam.ts]
  → WsSimSegmentInput[]
  → POST /api/workspace-sim/run
  → VerificationSegment[]
  → run_simulation() [backend/verification/simulation.py]
  → SimulationResult
  → WsSimResponse
```

## Stock Removal

The stock removal calculation uses `VOXEL_APPROXIMATION` fidelity
(`StockRemovalFidelity.VOXEL_APPROXIMATION`) when stock bbox is provided.

Stock volume metrics returned:

| Field | Description |
|-------|-------------|
| `initial_stock_volume_mm3` | Stock bbox volume (w × h × d) |
| `remaining_stock_volume_mm3` | Estimated volume after removing swept tool path |
| `removed_volume_mm3` | Difference |
| `stock_removal_fidelity` | `VOXEL_APPROXIMATION` or `UNKNOWN` |

If no stock bbox is provided → all volume fields are `null` (NOT_VERIFIABLE).
This satisfies **Hard Rule 11**: missing input → NOT_VERIFIABLE, never fabricated.

## Check Types

The Level-11 engine runs all 12 check types:

| Check | Type | Requires |
|-------|------|---------|
| PART_GOUGE | Gouge into part | part_bbox |
| STOCK_GOUGE | Gouge into uncut stock | stock, tool_diameter |
| TOOL_COLLISION | Tool body collision | fixtures, tool_diameter |
| HOLDER_COLLISION | Holder/spindle collision | fixtures, tool_length, holder |
| FIXTURE_COLLISION | Fixture body collision | fixtures, tool |
| RAPID_CLEARANCE | Rapid moves over fixtures | fixtures |
| MACHINE_ENVELOPE | Machine travel limits | machine_travel_x/y/z |
| OVERTRAVEL | Axis over-travel | machine_travel |
| AXIS_LIMIT | Per-axis limits | machine_config |
| TOOL_REACH | Tool vs pocket depth | flute_length |
| KINEMATIC_CHECK | Machine kinematics | machine_config |
| STOCK_REMAINING | Volume change verification | stock, tool_diameter |

If a required input is absent → check status = `INSUFFICIENT_DATA` (not FAIL,
not PASS). This prevents the engine from fabricating results.

---

## Verification State Derivation

```
BLOCKED             — no checks passed, all NOT_PERFORMED or INSUFFICIENT_DATA
FAILED              — at least one mandatory check FAILED
PARTIALLY_VERIFIED  — some mandatory checks PASS but not all
VERIFIED            — all mandatory checks for the requested profile PASS
```

A COMPLETED simulation with VERIFIED state means the requested profile's
mandatory checks passed for the given input data. It does NOT mean the part
is safe to manufacture.

---

## Simulation Fidelity Limitations

- Stock removal uses AABB (voxel) approximation — not exact swept volume
- Tool geometry uses a cylinder model based on `tool_diameter_mm`
- No actual holder or spindle geometry is modeled unless `holder_diameter_mm`
  and `holder_length_mm` are provided
- Fixture collision uses rectangular AABB models

For high-fidelity verification, use a dedicated CAM/verification system.

---

## Offline-Only Guarantee (Hard Rule 12)

The endpoint sets:
- `offline_only: true` in every response
- `simulation_result_is_not_machining_approval: true` in every response
- `safety.is_dispatchable: false` in every response

These cannot be overridden by any request parameter.

## Endpoint: `POST /api/workspace-sim/run`

**Auth:** Bearer token required

**Request:**
```json
{
  "toolpath_id": "tp-001",
  "segments": [
    {
      "start_x": 0, "start_y": 0, "start_z": 20,
      "end_x": 10, "end_y": 0, "end_z": 20,
      "motion_type": "RAPID",
      "is_cutting": false
    }
  ],
  "profile": "GEOMETRY_ONLY",
  "tool_diameter_mm": 6.0,
  "stock_bbox": {
    "min_x": -5, "min_y": -5, "min_z": 0,
    "max_x": 55, "max_y": 55, "max_z": 25
  }
}
```

**Response:** `WsSimResponse` — includes simulation_status, verification_state,
checks dict, volume metrics, visualization (cutting/rapid/collision/gouge points),
and safety invariants.
